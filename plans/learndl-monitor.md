# Learndl Monitor 单页控制台与 CLI 精简

## 目标与界面

新增独立于 Streamlit 的轻量网页控制台 **Learndl Monitor**，管理三个子服务。子服务显示为 **任务中心 / Task Center**、**存储洞察 / Storage Insights**、**研究工作台 / Research Workbench**，点击“打开”后在新标签页访问。

采用深灰蓝背景、青绿色状态强调色、清晰的等宽数字，适合研究与运维场景。页面仅包含顶部机器信息、三个服务卡片和可展开的日志区域，窄屏自动纵向排列。

每个卡片显示服务说明、运行状态、来源（控制台启动／外部发现）、PID、端口和运行时长。主操作统一为“启动、打开、重启、关闭”。Storage Report 额外显示快照时间和“重新扫描”。

## 服务生命周期与外部接管

- 打开控制台时先检测实际状态，不自动启动子服务。未运行的服务显示“已关闭”；已有服务显示真实运行状态。
- 状态包含检测中、已关闭、启动中、运行中、重启中、关闭中和异常。仅已关闭时启用“启动”；运行中启用其他三项；进行中的操作禁止重复提交。
- 启动采用脱离终端的后台进程，日志写入本地轮转文件。通过进程身份、监听端口和健康检查确认就绪，失败时展示原因与日志摘要。
- 关闭网页后控制台和子服务继续运行。再次进入复用同一控制台进程，并重新核对服务状态。
- 重启与关闭先弹出确认，明确服务、PID 和来源。先正常终止，超时后才对经过身份复核的目标进程及其子进程强制结束。
- 外部发现结合当前用户、项目绝对路径、服务入口参数、PID 创建时间和监听端口，避免仅凭进程名或端口接管。多个有效实例按创建时间、PID 排序，选最早实例，并显示额外实例数量。
- 控制操作再次验证身份，防止 PID 被复用。多个网页会话共享服务锁；启动前重新检测，避免重复启动。未能停止旧实例时，重启流程终止并显示错误。
- 服务登记保存 PID、创建时间、项目路径、服务类型、端口、访问地址及启动配置。更新现有启动入口，使以后从终端启动的服务也能被发现。
- 旧版存储浏览进程若缺少登记信息且无法恢复访问令牌，显示“发现旧实例，访问地址不可恢复”。身份可验证时允许确认后重启迁入；身份不足时显示原因并禁用控制操作。

## 实现与存储报告

**控制台实现**

使用 Python 轻量 HTTP 后端和原生 HTML/CSS/JavaScript，放入独立的 `src/api/learndl_monitor/` 模块。控制台启动路径只加载服务管理所需依赖，浏览器约每 2 秒更新状态。

提供固定服务 ID 的状态查询、启动、重启、关闭、日志读取和存储重扫接口。后台异步执行耗时操作，页面显示进度与结果。接口只接受已配置服务及操作。

默认仅监听 `127.0.0.1`，控制台使用本地访问令牌、同源校验和 POST 操作。令牌及运行登记保存在仅当前用户可读的运行目录。默认端口为控制台 8500、Streamlit App 8501、Task Monitor 8502、Storage Report 8503，支持配置调整；端口被无关进程占用时明确报错。

本机入口自动打开浏览器。服务器无桌面环境时输出访问地址和 SSH 转发命令，覆盖控制台与三个服务端口；接管自定义端口服务时补充对应转发信息。

**Storage Report**

复用现有扫描、HTML/SQLite 快照和浏览服务实现，默认扫描根目录沿用 `PATH.production`。

启动优先选择当前机器、当前扫描根目录下最新且校验有效的快照；没有有效快照时在后台首次扫描。首次自动生成不发送邮件；点击“重新扫描”默认发送邮件。

“重新扫描”后台生成新快照，期间继续提供旧报告。新快照通过校验后切换浏览内容；扫描失败保留旧报告并显示错误。关闭服务时取消未完成扫描，未完成文件不进入可选快照列表。

为现有 `StorageReportServer` 增加可选固定端口和服务登记支持，保留原调用方式的兼容性。
